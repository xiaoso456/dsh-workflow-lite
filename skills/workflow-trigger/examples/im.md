# 聊天软件、SaaS 平台推送的事件（飞书、钉钉、企业微信、Slack……）

这类平台各有各的接法，没有一份脚本能照抄。按下面的顺序定方案，再照对方的文档写。

## 1. 先看对方给哪种接法

| 对方提供 | 用 | 说明 |
|---|---|---|
| 长连接（飞书「长连接」、钉钉 Stream 模式、Slack Socket Mode 之类） | 监视 | 首选：本机主动连出去，不用公网地址、不用握手验证 |
| 只有事件回调（Webhook），且要握手、校验签名、读请求头 | 监视，脚本自己开端口 | 写法同 `examples/github.md`；对方在外网时还要用户配隧道或转发 |
| 只有事件回调，直接 POST、不验证 | `http` | 地址后面带 `?token=<令牌>` |
| 都没有，只能调接口查 | 定时检查，`when: "every"` | 脚本记下查到哪了，有新的才打出、退出 0 |

拿不准就请用户把对方「事件订阅 / 机器人」设置页的文档链接给你，读过再定。

## 2. 写监视程序

- 用对方官方的 Node SDK，在 `dir/triggers/` 放 `package.json` 并装好；接口以对方当前的文档和 SDK 的类型定义为准，不要凭记忆写。
- 应用的 ID、密钥请用户放进 `TRIGGER_DATA_DIR` 下的一个 JSON 文件或环境变量，脚本去读；缺了就往错误输出写清楚缺什么、退出非 0。
- SDK 往往自己往标准输出打日志：开头把 `console.log` 改道到错误输出（见 `scripts.md`），能调日志级别的调到只报错。
- 收到一条要处理的事件打一行 JSON，只留执行的模型要的字段：哪个会话、谁发的、文字（富文本、卡片消息先取出纯文字）、消息编号。机器人自己发的、和要做的事无关的事件类型在脚本里丢掉。
- 对方会重投同一个事件（没及时确认、重连之后）：按消息编号去重，记在 `TRIGGER_DATA_DIR`。
- 要回消息时，让工作流的步骤去回（用同一个应用的接口），不要在监视程序里回。

## 3. 试

`test_trigger` 的 `seconds` 写 30 到 60，请用户在这段时间里给机器人发一条消息。看：

- `lines` 里正好一行，内容是上面那几个字段；
- `run.stderr` 里没有报错（连不上、鉴权失败多半是 ID、密钥或权限没开）；
- 没有 `run.exited`。
