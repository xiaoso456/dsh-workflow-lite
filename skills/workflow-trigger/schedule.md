# 定时 `schedule`

写之前先按 SKILL.md 的「找示例」挑一份照着改：带检查的看 `examples/pending.md`（有待办才做）、`examples/web-change.md`（变了才做）、`examples/git-commits.md`（接着上次看到的往后看），特殊日子看 `examples/last-workday.md`、`examples/once.md`。

`schedule` 三种写法，都按这台机器的时区：

| 写法 | 字段 | 说明 |
|---|---|---|
| `{ "kind": "daily", "time": "09:00" }` | `time` 必填；`moreTimes` 同一天另外几个时刻；`weekdays` 只在星期几（1 = 周一 … 7 = 周日，不写 = 每天） | 一天最多 12 个时刻 |
| `{ "kind": "every", "seconds": 300 }` | `seconds` 间隔 | 到点直接执行的最短 60 秒，带检查的最短 10 秒，最长 7 天 |
| `{ "kind": "cron", "expression": "0 9 * * 1-5" }` | 五段：分 时 日 月 周 | 支持 `*`、数字、`a-b`、`*/n`、`a-b/n`、逗号列表；周的 0 和 7 都是周日；不支持 `MON`、`L`、`?` 这类写法 |

例子：工作日 9 点和 14 点 → `{ "kind": "daily", "time": "09:00", "moreTimes": ["14:00"], "weekdays": [1,2,3,4,5] }`；每月 1 号 8 点 → cron `0 8 1 * *`。

到点就执行（不带 `check`）：

- 「每隔」从打开开关时算起；每天几点、cron 按钟点。
- DSH 没开着时错过的，`launch.catchUp`（缺省 true）为真就在 DSH 启动后补一次，错过几次都只补一次；为假就跳到下一次。

## 带检查命令 `check`

到点先在卡片目录里（设了 `local.cwd` 就在那里）跑一次 `check.command`，按判定 `check.when` 决定触不触发：

- 退出码 0 = 条件满足，非 0 = 不满足。不满足是正常结果，不算失败。
- 标准输出就是这次的背景信息，原样交给执行的模型；错误输出只给人排查用。要在标准输出里打日志（查了几条、用了多久），就把要交出去的那几行写成 `::trigger::` 开头：有这种行时只有它们（去掉标记）是背景信息、拿来比较，别的都是日志。
- 命令要很快结束：「每隔」的不能超过间隔，都不能超过 5 分钟；超时、找不到命令、启动不了算一次失败，连续几次（`launch.maxFailures`，缺省 3）自动停用。
- 不要等输入，不要弹窗。

| `when` | 什么时候触发 | 适合 | 第一次 |
|---|---|---|---|
| `every`（缺省） | 每次退出码 0 | 命令自己判断「有没有要处理的」：有就打出要处理的、退出 0，没有就退出 1 | 满足就触发 |
| `success` | 上一次不满足、这一次满足 | 等某件事完成：部署好了、服务起来了、文件出现了。条件一直成立不会反复触发 | 满足就触发 |
| `change` | 退出码 0 且输出和上一次不一样 | 网页变了、有新提交、版本号变了：命令只要打出当前的状态 | 只记下、不触发 |

- `every` 处理完一件事，命令下一次要返回非 0（或不再打出这件事），否则每个间隔都会再触发；靠 `launch.overlap` 和 `maxPerHour` 兜底，别为了这个调大间隔。
- `change` 比较的是背景信息（有 `::trigger::` 行时只比这几行，没有时比整段标准输出）：里面带时间戳、随机数、计数器，每次都会触发。只交出关心的那部分。
- 返回非 0 的那次，`change` 不拿来比较，`success` 记成「不满足」。
- 第一次打开开关时，「每隔」马上查一次，之后每次查完隔一个间隔再查（跑得久不会叠着跑）；每天几点、cron 按钟点查。
