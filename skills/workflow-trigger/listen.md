# 监视 `listen`

打开开关时插件启动这条命令，关掉时结束它；意外退出按 2 秒起翻倍、最长 1 分钟的间隔重启。

## 只有 `::trigger::` 开头的行会触发

程序往标准输出打一行以 `::trigger::` 开头的，就是一件事：标记后面的内容（去掉首尾空白）是这件事的背景信息，过了过滤就发进会话执行一次工作流。

别的输出都是日志：不带标记的标准输出、全部错误输出，都只记进「最近的输出」给人看，不触发。所以：

- 日志照常打：启动了、查了几条、状态没变、连不上在重试，用 `console.log` 打到标准输出就行，用户在「最近的输出」里看得到。错误输出留给真出错的情况（界面上会标成错误）。
- 第三方库、子进程打到标准输出的也只是日志，不用改道。
- 要触发的那一行一定要自己带上标记，统一用一个函数打：

```js
// text：一句话说清这件事，动态拿到的文字直接拼进来；data：要原样给出的字段（可选，跟在后面成一段 JSON）。
// 换行一律换掉：一件事只能占一行，不然后面几截没带标记，只算日志。
const emit = (text, data) => {
  const line = data === undefined ? String(text) : `${text} ${JSON.stringify(data)}`
  console.log(`::trigger:: ${line.replace(/\r?\n/g, ' ⏎ ')}`)
}
```

## 一件事打成什么样

执行的模型只看得到标记后面这一段（加上卡片上的触发说明），看不到程序之前打过什么，也不知道它是从哪来的。

- 一段要自带做事需要的上下文：哪个文件、哪个仓库、哪个人、哪条消息、出了什么事。开头一句话说清这件事，动态拿到的文字直接拼进来；要原样给出的字段放进 `emit` 的 `data`。
- 一行对应「一件值得跑一次工作流的事」，不是原始流水的每一行：每次执行都要开会话、跑完整个工作流。能在脚本里先归并的就先归并（报错和它后面的堆栈是一件事，同一个请求的几行日志是一件事）。
- 一件事只能占一行：堆栈、消息正文这类动态内容随时带着换行，直接拼进去的话只有第一截带标记，后面几截只算日志，背景信息少了一块还不报错。用上面的 `emit` 就不用操心；`test_trigger` 看出来时会在 `notes` 里提醒。
- 要做的事（「找出原因、写进 report.md」）和字段的意思写在触发说明里，不用每行都带；行里只放这件事本身。
- 别放每次都变、又不是这件事本身的东西（脚本自己打的时刻、自增编号），不然去重永远不算重复。
- 大的内容（整份文件、截图、长报告）写成文件，行里只给路径。

| 不好 | 好 |
|---|---|
| `ERROR pay failed`（没带标记，只是日志） | `::trigger:: app.log 出现报错：10:02:03 ERROR pay failed: timeout {"stack":["at Pay.charge(Pay.java:42)"]}` |
| `::trigger:: new file` | `::trigger:: D:/inbox 进了新文件 a.pdf {"path":"D:/inbox/a.pdf","size":10240}` |
| `console.log('::trigger:: ' + message)`，消息正文带换行，后面几行成了日志 | `` emit(`#ops 频道 alice 发来：${message}`) ``，换行换成 ⏎ |
| `::trigger:: [10:02:03.417] main 有新提交`（时刻是脚本自己打的） | `::trigger:: main 有新提交 3f2a1c9：Fix login` |

## 几行事件怎么算成几次

1. 每一行事件（以换行结束，`\r\n` 也行）算一段；一行超过 64 KiB 会被切开，只有带标记的第一截算数。
2. 关键字（`filter.include` / `exclude`）逐段判断，过不了的直接丢掉，不记进触发记录。
3. 去重（`filter.dedupe`）：和去重时长内已经收过的一段一字不差才算重复。带时间戳、编号的几乎不会重复；要按「同一种事」去重，在脚本里把会变的部分去掉再比，或者调大合并窗口。
4. 合并（`filter.merge`，监视缺省 5 秒）：从第一段通过时开始计时，这段时间里通过的几段并成一次执行，背景信息是这几段按先后用换行连起来，消息里注明是几次合并的。窗口不顺延：一直有事件进来时，每个窗口触发一次。写 `0` 是每段马上单独触发。
5. 合并之后的这一次，再按执行设置决定发不发：
   - 上一次触发的执行还没结束时，`overlap` 缺省 `skip` 是跳过：这次不执行，触发记录里留着（能看到内容）。每件事都不能漏的用 `queue`（最多排 `queueMax` 个），或调大 `merge` 让一段时间里的事并成一次。
   - 这一小时已经发出、排进队的次数到了 `maxPerHour`（缺省 60）就丢掉，十分钟里只记一条「到上限了」。

所以「一行事件执行一次」要同时满足：这一行过了过滤、合并窗口是 0、没被「上次执行未结束」挡下（`parallel` 不挡）、没到每小时上限。事件来得密时，先想好要「每件都处理」（排队）、「一段时间处理一次」（调大合并）还是「忙的时候丢掉也行」（跳过）。

## 启动时不打事件

程序每次启动（打开开关、DSH 重启、程序退出后重启、改了设置）都从头运行。启动时只记下现状、打日志，别把已有的东西当成新事件打出来，否则每次重启都会触发一遍。读到哪了记进 `TRIGGER_DATA_DIR`，启动时接着读（见 `examples/folder.md`、`examples/log.md`）；状态文件不存在才是第一次，第一次只记下现状。

## 运行

- 打完一行马上刷新输出：Node 的 `console.log`、`process.stdout.write` 可以；Python 要 `print(..., flush=True)`。
- 一直运行，收到结束信号就退出。不要自己转后台（`&`、`nohup`、`start`、守护进程）：插件管不到它，关掉卡片也停不下来。
- 启动后 1 分钟内就退出算一次失败（脚本有错、依赖没装、连不上）；跑满 1 分钟之后再退出只重启、不算失败。
- DSH 没开着的时候没人收事件；不想漏掉这段时间的事，就靠 `TRIGGER_DATA_DIR` 里记的位置在启动时补上。
- 别打终端颜色码，会原样进背景信息。用 UTF-8 输出（Node 缺省就是）。
- 想直接盯一个现成的命令行程序（`docker events`、`kubectl get -w`、消息队列客户端），它打的行没有标记：写个 Node 脚本把它作为子进程跑起来，读它的输出，挑出要处理的那几行加上标记打出来（见 `examples/mq.md`）。
