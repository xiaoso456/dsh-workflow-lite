## 循环

连线指回前面的步骤，就形成循环。典型用法是「审查 → 修复 → 再审查」：未通过就返工，通过后继续往下。

![审查未通过时回到修复，形成循环；通过后走向汇总](../../../assets/shots/graph.webp)

搭建：

1. 「实现」→「审查」。
2. 「审查」→「修复」，条件选「未通过」。
3. 「修复」→「审查」，形成循环。
4. 「审查」→「汇总」，条件选「通过」，这是循环的出口。

注意：

- **循环必须有出口**。没有出口时计划会标明「没有出口」，「检查」面板也会警告。
- 没有单独的「最多几轮」设置。需要限制时，写在提示词或自定义条件里，如「审查未通过，且修复不足三次」。
- 实例里每回到一个步骤，轮次加 1，显示为「第 N 轮」，可在步骤面板用「加一轮」「减一轮」调整。
- 写出产出文件的步骤每做完一轮保存一个版本，见[各轮产出回看](/dsh-workflow-lite/display/rounds/)。
- 开启「记录运行状态」后，中断可以接着执行，从记录的步骤和轮次继续。

循环不限于代码审查：「搜集候选方案 → 评估与筛选」，不满意就回去再搜一轮，满意再汇总，同样适用。

## 并行与汇合

- **并行**：一个步骤引出多条线，连到不同的下游，下游互不依赖。
- **汇合**：多条线连到同一个步骤，它在所有上游完成后才开始。

点击「预览计划」，在「执行批次」里可以看到：互不依赖的步骤在同一批，汇合的步骤排在后面，「前置」列出所有上游。

是否真的同时执行，取决于[工作流设置](/dsh-workflow-lite/settings/workflow/)的「执行方式」：「串行」逐个完成，「主 agent + 子代理」可一起派给子代理，「Agent 团队」由队员分别负责，「自动」由主 agent 决定。

条件连线互斥，与并行不同。需要同时进行的分支，使用条件为「总是」的连线。
