触发器可以交给模型来建：在对话里说明想在什么时候执行哪个工作流，模型选触发方式、写好要运行的脚本、先试一遍，再在工作流里加一个触发器。模型建的触发器一律是停用的，检查后由用户自己启用。

## 使用

1. 在对话里说明要求，例如「`logs/app.log` 里出现 ERROR 就执行工作流『日志巡检』，脚本写好并试通」。
2. 模型把脚本放进工作流目录的 `triggers/` 里，试运行看输出，再加触发器、填好触发说明和执行设置。
3. 模型最后说明还要用户做什么：通常是在画布上选中这个触发器，核对命令和工作区，打开「启用」并点击「确认并启用」。
4. 工作流没开「记录运行状态」、或图本身还有问题时，模型会一并指出。

脚本写在工作流目录里，命令里用 `{workflow}` 指向它，换了工作区也能用；工作流导出时脚本随之带走。

## 排查

触发器显示「出错」「已自动停用」，或该触发时没触发，可以直接让模型看看，例如「『日志巡检』的触发器停了，查一下原因」。模型能读到各触发器的状态、触发记录、最近的输出和排队情况，改好后再试一次，然后请用户重新启用。

## 设置

模型按需读取的使用指南由[插件设置](/dsh-workflow-lite/settings/plugin/)里的「给模型的使用指南」控制，默认开启；关掉后模型仍能建触发器，但不再有选触发方式、写脚本、排查的指引。

## 注意

- 模型不能启用触发器，也不能替用户确认命令；要在本机运行的命令只有用户确认过才会运行。
- 插件的数据目录不在当前工作区里时，模型往工作流目录写脚本会请求批准。
- 命令以 DSH 的身份运行、不进沙箱：启用前读一遍模型写的脚本。
