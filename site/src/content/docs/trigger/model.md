触发器可以交给模型来建：在对话里说明想在什么时候执行哪个工作流，模型选触发方式、写好要运行的脚本、先试一遍，再在工作流里加一个触发器并启用。

## 使用

1. 在对话里说明要求，例如「`logs/app.log` 里出现 ERROR 就执行工作流『日志巡检』，脚本写好并试通」。
2. 模型把脚本放进工作流目录的 `triggers/` 里，试运行看输出，再加触发器、填好触发说明和执行设置。
3. 试通后模型启用触发器，并说明它会在什么时候触发、运行什么命令、在哪个工作区运行。要先检查再启用的，在要求里说明「先别启用」。
4. 工作流没开「记录运行状态」、或图本身还有问题时，模型会一并指出或改好。

要停用、重新启用触发器，也可以直接在对话里说。

脚本写在工作流目录里，命令里用 `{workflow}` 指向它，换了工作区也能用；工作流导出时脚本随之带走。

## 排查

触发器显示「出错」「已自动停用」，或该触发时没触发，可以直接让模型看看，例如「『日志巡检』的触发器停了，查一下原因」。模型能读到各触发器的状态、触发记录、最近的输出和排队情况，改好后再试一次，然后重新启用。

## 设置

模型按需读取的使用指南由[插件设置](/dsh-workflow-lite/settings/plugin/)里的「给模型的使用指南」控制，默认开启；关掉后模型仍能建触发器，但不再有选触发方式、写脚本、排查的指引。

## 注意

- 模型启用要运行命令的触发器时，等同于在画布上点击「确认并启用」；之后命令、工作区或 shell 改了，要重新确认才会运行。
- 插件的数据目录不在当前工作区里时，模型往工作流目录写脚本会请求批准。
- 命令以 DSH 的身份运行、不进沙箱：模型写的脚本和命令最好读一遍，不放心的先让模型别启用。
