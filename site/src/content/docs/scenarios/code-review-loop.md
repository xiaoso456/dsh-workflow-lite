每次改动都经过独立审查，不通过就返工，直到通过。

```
实现 → 审查 ──通过──→ 汇总
         │
      未通过
         ↓
        修复 ──→ 回到「审查」
```

![审查未通过时回到修复，形成循环；通过后走向汇总](../../../assets/shots/graph.webp)

## 搭建

1. 从步骤库「常用步骤」拖出「实现」「审查」「修复」「汇总」。内置的「审查」已要求给出通过或不通过的判定。
2. 在各步骤的提示词里写这次任务的要求，如实现的功能和约束、审查的重点、汇总的格式。
3. 连线：
   - 「实现」→「审查」，条件「总是」。
   - 「审查」→「修复」，条件「未通过」。
   - 「修复」→「审查」，形成循环。
   - 「审查」→「汇总」，条件「通过」，这是出口。

连线操作见[连线与条件](/dsh-workflow-lite/editing/steps/#连线)，概念见[循环与回退](/dsh-workflow-lite/editing/loops/)。

可选：

- **留住审查结论**：给「审查」添加产出文件 `review.md`，让「修复」读取它，每轮细节不会因交接只传要点而丢失。
- **限制轮数**：把「审查 → 修复」的条件改成「自定义」，写「审查未通过，且修复不足三次」，并在「审查」提示词里写明满三次后仍给出通过判定并列出遗留问题。

## 执行

打开「记录运行状态」后点击「执行」，在实例里可看到「审查」「修复」当前第几轮，必要时用「加一轮」「减一轮」调整。中断后从记录的位置接着做。

![第二轮审查正在执行，已完成的步骤点亮](../../../assets/shots/run-graph.webp)

每一轮的产出版本可以回看，见[各轮产出回看](/dsh-workflow-lite/display/rounds/)。
